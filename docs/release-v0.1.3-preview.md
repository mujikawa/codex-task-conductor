# Task Conductor v0.1.3-preview

This preview converts a five-worker serial delivery observation into tighter
context inheritance, validation ownership, and AGY execution sequencing.

## What changed

- Worker creation now records whether it inherits no history, the smallest recent
  slice containing indispensable trusted authorization, or an evidenced
  full-history exception.
- Validation ownership is split between worker semantic and focused checks, one
  immutable-candidate repository-wide gate, and one final integration gate.
  Duplicate broad gates require repository policy, a relevant intervening change,
  an inconclusive infrastructure failure, or an explicit risk rationale.
- AGY dispatch packets now declare the final output shape and objective-specific
  probes that can detect an unexplained no-op, missing module tree, increased
  monolith size, unchanged required metric, or value-equivalence failure.
- AGY task validation and likely remediation are ordered before large ignored
  runtime trees when dependencies permit. When early materialization is required,
  the packet declares the bounded Codex capability handoff instead of deleting an
  environment to regain wrapper eligibility.

## Why

The observed initiative completed five serial outcomes, GitHub reconciliation,
migration, and deployment, but full-history inheritance, repeated broad gates,
and host approval review dominated Codex input. Four AGY-backed outcomes all
benefited from Codex semantic review or capability handoff, including one valid
`SUCCESS` receipt with no useful diff. The new controls preserve that acceptance
quality while reducing avoidable context and validation repetition.

## Installation

Ask Codex:

```text
Use $skill-installer to install skills/task-conductor from
mujikawa/codex-task-conductor at ref v0.1.3-preview.
```

Restart or reload Codex after installation. `$delegate-to-agy` remains a separate
optional dependency and should use its matching v0.1.3 release for the complete
sequencing and semantic-probe contract.

## Preview limitations

- The source observation is not a controlled time, token, or cost benchmark.
- Minimal trusted-turn inheritance depends on the worker-creation surface
  preserving direct user authorization.
- Repository policy may still require repeated broad gates at distinct immutable
  or deployment boundaries; this release requires recording the reason rather
  than suppressing those gates.

Worker creation, AGY disclosure, publication, deployment, credentials, cleanup,
and other external side effects remain behind their explicit authorization
boundaries.
